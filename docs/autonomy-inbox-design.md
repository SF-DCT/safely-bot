# mamo 自律化 — 業務の受付箱（Work Inbox） v0.2

> 更新: 2026-09-30 ／ 状態: Phase 1 実装済み
> v0.1 からの変更（高橋さんの指示）: メール返信は対象外／主役は「意思決定に必要なデータ分析・整理」／返信待ちに限らず、これまでの依頼から拾う／Slack 返信は下書きまでで、送信前に必ず確認

## 1. ゴール

高橋さんに来た依頼のうち、追いつけていないもの・手間がかかって止まっているものを mamo が拾う。
代わりに分析・整理を完遂し、高橋さんには「判断すること」だけを返す。

## 2. 流れ

```
① 拾う   mamo（Railway）が平日 9:30 / 14:00 に Slack を検索（高橋さん宛てのメンション＋DM）
           初回は14日分、以降は前回からの差分
② 仕分け Claude Opus 5.5 が「未完了の依頼か／種類／代わりにできるか／止まっていそうな理由」を判定
③ 提案   DMに1件ずつカード（最大8件、残りは次回）
           [🔍 進めて] [📝 返信の下書き] [🕒 明日に回す] [✅ 対応済み] [❌ 対象外]
④ 実作業 🔍 → 高橋さんのPCの worker が Claude Code（claude -p）で分析・整理
           報告は Private/mamo-work/ に保存、DMには「事実／見立て／次の対応／相談事項」
           [📝 返信の下書き] [🔁 指示を足してやり直す] [✅ 完了にする]
⑤ 返信   📝 → 下書きカード（まだ送らない）
           [✅ この内容で送信] [✏️ 直す] [🗑 送らない]
           22時〜翌5時は [⏰ 明朝8:30に送信] を先頭に出す
```

## 3. 権限

| 操作 | 誰が | 承認 |
|---|---|---|
| Slack の検索・読み取り、仕分け | mamo | 不要 |
| 分析・整理（読み取りのみ） | PCの Claude Code | 🔍 を押したとき |
| 返信の下書き作成 | mamo | 📝 を押したとき |
| 高橋さん名義での送信 | mamo（ユーザートークン） | 下書きを見て ✅ を押したときだけ |
| メール返信、予算・支出・契約・削除 | — | 対象外 |

## 4. 実装の場所

| 部品 | ファイル |
|---|---|
| 拾う・仕分け・カード・下書き・送信 | `src/data-sources/work-inbox.ts` |
| 定時実行（平日 9:30 / 14:00） | `src/scheduler/work-inbox.ts` |
| ボタン・モーダル | `src/index.ts`（`work_*` アクション） |
| DMからの手動実行 | ツール `scan_work_requests`（「依頼を拾って」） |
| 状態 | Neon `work_items`・`mamo_kv`（`src/data-sources/database.ts`） |
| PC側の実作業 | `worker/work-runner.mjs`（手順は `worker/README.md`） |

## 5. リスクと対策

| リスク | 対策 |
|---|---|
| 高橋名義での誤送信 | 送信は下書きカードの ✅ だけ。✏️ で直しても送らない |
| 分析中の Claude Code が外部へ書き込む | 秘密情報を渡さない／禁止ツールリスト／auto モード＋厳守事項の3重。完全な隔離ではない |
| 通知が多すぎる | 1回8件まで・❌ は二度と拾わない・🕒 は翌朝に再提案 |
| 仕分けの精度（4月に返信待ち検知を止めた理由） | 初週は結果を見て、❌・✅ の比率で調整する |
| PCが止まっていると進まない | 作業待ちのまま残り、次に起動したとき処理する |
| API 費用 | 仕分けは1回あたり最大80スレッド（初回が最大）。Opus 5.5 の単価で1回およそ1ドル前後の見込み（未実測） |

## 6. 次のフェーズ候補

- 拾う範囲の拡大: 議事録（post-meeting の出力）、Asana / Notion の期限タスク、広告の異常検知
- 週次の成績表: 提案数・🔍率・❌率・下書きの修正率
- 承認率の高い種類を「分析まで自動で着手」に上げる（高橋さんが決める）
